# Quote measurement and attribution

The quote calculator now sends optional, sanitized first-party measurement context with the final `/api/quote` request. The operational quote session is separate from the anonymous browser measurement session. First touch, latest non-direct touch, landing **category**, and token-only source/medium/campaign survive the Shed quote record and existing authenticated CRM sync. This new context excludes dynamic project/city/article slugs, raw query strings, referrer paths, contact answers and amounts. Recognized AI sources are ChatGPT, Perplexity, Claude, Gemini and Copilot; a `utm_source=chatgpt.com` link becomes `chatgpt`. UTM values reject common credential prefixes, long digit runs and UUIDs, but campaign authors must still avoid personal or secret information in campaign names. Existing separate GA/Vercel `quote_success` events and their quote ID/amount properties are unchanged by this work.

The existing browser opt-out, DNT and GPC gates apply. The quote API independently drops optional context when DNT or GPC is present. Missing context stays unknown; it is never reconstructed from the operational quote session or labeled as direct traffic. SMS consent is unchanged and independent.

Measurement boundaries:

- Continue buttons remain step navigation, not accepted requests. Clarity's automatic Submit form event can still include them.
- `quote_request_saved` is a Clarity custom event emitted only after the quote API returns a valid saved quote response, once per quote per mounted page. It carries no contact data, quote ID or amount, honors browser measurement privacy, and is restricted to the production site host. It is an optional browser signal and can be blocked.
- `quote_request_saved` first deployed 2026-09-22 (#805); Clarity reports before 2026-09-23 cannot contain it.
- `quote_step_1_size`, `quote_step_2_materials` and `quote_step_3_contact` are Clarity custom events for the first time a mounted `/quote` page shows each step, with the same privacy and host gates and no form data. Build a Clarity funnel from those three plus `quote_request_saved` to see which step loses people; don't use Submit form for that, because it counts every Continue tap. Reports from before these events deploy cannot contain them.
- The Google tag and Clarity both load only when `VERCEL_ENV` is `production`, so localhost and Vercel Preview QA no longer reach GA (GA DebugView will not see previews either). GA data from before that gate includes those hits; filter GA explorations to Hostname exactly `www.shed210.com`, where production redirects the apex and other aliases.
- CRM's existing `quote-request` confirmed goal is recorded only after authenticated quote ingestion succeeds. It uses the same stable quote-based event identity, deduplicates delivery retries, and retains the optional browser session/attribution. Preview source deployments, backfills and recognized test/staff records remain excluded. No extra notification is introduced.
- An accepted request is not a unique new prospect, qualified opportunity, order, or revenue. Quote rows connect to their existing CRM lead through the source-owned projection. Staff must maintain lead qualification/order outcomes before reporting source-to-sale performance; this change does not infer those outcomes or backfill unavailable historical sources.

Clarity recording masking: Clarity masks the quote inputs themselves (name, email, phone, build address) in every mode. The quote sidebar's Build location row echoes a typed, autofilled or prefilled address as plain text, so its value carries `data-clarity-mask="true"`, which masks it whatever the project mode. Build selections and estimate prices are deliberately left unmasked: they are not personal data and are the main evidence when diagnosing quote drop-off. Any other page text depends on the project-level mode in Clarity Settings > Masking: Balanced (Clarity's default) masks numbers and email addresses, Strict masks all text, and Relaxed masks no text outside inputs. Never set the project to Relaxed. The privacy policy still says quote form details are not intentionally collected in recordings, which is broader than this: proposed replacement copy (contact details and build addresses masked; build selections and estimated prices may appear) is pending owner approval, so update the policy before relying on selections or prices in recordings. Recorded mode: not yet confirmed; check Settings > Masking and update this line. Masking changes are not retroactive: `/quote` recordings made before the Build location mask shipped can show the street name and city in the sidebar, so review them before exporting or sharing.

The sticky Instant Price links on an already-mounted `/quote` now focus and scroll to the active step (or the existing result) without remounting or clearing inputs. Modified/new-tab clicks retain normal link behavior.

Rollout: deploy the compatible CRM receiver first, then Shed. The only schema additions are optional quote measurement and AI referrer enum members. Old records and payloads remain valid; no migration, secret, or feature activation is required. Existing first-party event forwarding still requires `FRONTIER_PIXEL_CRM_WEBSITE_EVENTS_KEY` and an enabled/configured CRM website-performance installation. The older CRM HTTP receiver ignores the extra field, so reversing deployment order loses attribution on those intervening submissions. Validate with mocked local tests and isolated preview data; do not create a production test lead because normal quote acceptance schedules notifications.
